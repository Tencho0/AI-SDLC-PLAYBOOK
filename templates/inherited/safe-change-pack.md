# Safe Change Pack

> Produced to plan and make a low-risk change to inherited code without breaking hidden behavior. Save the filled copy to `src/<engagement>/delivery/`.

## 1. Issue summary
_What the change is meant to address._

## 2. Root cause hypothesis
_The suspected underlying cause._

## 3. Affected files
_The files the change is expected to touch._

## 4. Business rules involved
_The business rules this change interacts with._

## 5. Regression risks
_Where the change could disturb existing behavior._

## 6. Suggested tests
_Tests to add or run to protect against regressions._

## 7. Implementation plan
_The step-by-step plan to make the change safely._

## 8. Code changes
_A summary of the code that was changed._

## 9. Documentation updates
_Documentation that needs updating as a result._

## 10. PR risk notes
_Risk notes for the reviewer to consider._
